# Specdown iOS

Swift + WKWebView app wrapping the shared `markdown-viewer/` web codebase.

## Prerequisites

- Xcode 16+ (iOS 16 SDK)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`

## Getting Started

```bash
# From the repository root, build the shared viewer first:
npm run build
cd ios
xcodegen generate
open SpecDown.xcodeproj
```

Select the **SpecDown Dev** scheme, then an iPhone or iPad simulator and Run.
Device signing is a separate owner-led setup. The unsigned validation command
below does not register identifiers or create profiles. When the owner later runs
on a physical device, Xcode automatic signing may register the selected app ID and
create its provisioning profile using the owner's account.
Before regenerating an existing local project, preserve its owner-managed signing
and workspace settings; the generated `.xcodeproj` is ignored by Git.

For a reproducible command-line build on machines with different simulator inventories, prefer the generic simulator destination:

```bash
xcodebuild -project SpecDown.xcodeproj \
  -scheme 'SpecDown Dev' -configuration 'Dev Debug' \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```

## Development channels

One source target produces three separately installed apps:

| Scheme | Bundle identifier | Run configuration | Archive configuration | Display name / default icon |
| --- | --- | --- | --- | --- |
| `SpecDown Dev` | `com.mosaicpando.specdown.dev` | `Dev Debug` | `Dev Release` | SpecDown Dev / Flat |
| `SpecDown Beta` | `com.mosaicpando.specdown.beta` | `Beta Debug` | `Beta Release` | SpecDown Beta / Light |
| `SpecDown` | `com.mosaicpando.specdown` | `Debug` | `Release` | SpecDown / Original |

Choose the scheme explicitly. All three retain the same eight manual icon choices,
with a channel-aware reset to the default. Their preferences, recents and WebKit
storage are private to their separate app sandboxes; no shared App Group or data
migration is configured. The internal `specdown://app` origin is unchanged. Files
documents stay where the user keeps them and can be deliberately opened in any
channel; this change does not copy them between installations.

Dev is the local development app. Beta uses a separate owner-created App Store
Connect record for TestFlight only. The existing production ID remains the release
identity: the final production build must pass its own TestFlight gate before App
Review. New IDs and profiles are owner-led setup; valid existing certificates can
be reused where appropriate. No account actions or signing are part of this source
change. See the [channel contract](../docs/project-appstore/2026-10-31-spec-ios-development-channels.md)
for isolation, verification, provisioning references and rollback limits.

## Web Assets

The shared web app is a Vite + ES-module build. Run `npm run build` at the repo
root first; its output, `markdown-viewer/dist/`, is bundled into the app as a
folder reference (available at runtime as `dist/index.html`). The CI workflow
(`.github/workflows/ios.yml`) runs the build before generating the Xcode
project; for local builds run `npm run build` before `xcodegen generate`.

Bundled sample markdown files live at `markdown-viewer/samples/` and are copied
into `dist/samples/` by the build, where they ship inside the app bundle for
smoke testing and can be opened from the iOS drop screen.

External links opened from inside the viewer stay in the system browser instead of navigating the embedded app shell away from its bundled content.

On iPad in regular-width layouts, the SwiftUI shell presents a native sidebar for opening files and samples while the shared viewer stays in the detail pane.

## Safe Area Handling (Dynamic Island, Notch, Home Indicator)

The iOS app uses a layered approach to handle safe areas properly on devices with Dynamic Island, notches, and home indicators:

### SwiftUI Layer (`ContentView.swift`)
```swift
WebView(bridge: bridge)
    .ignoresSafeArea()  // Phone layout only — extends WebView edge-to-edge
```

On iPhone, the WebView extends under the status bar, Dynamic Island, and home indicator. On iPad in regular width, safe areas are respected natively by the split view.

### WKWebView Layer (`WebView.swift`)
```swift
webView.scrollView.contentInsetAdjustmentBehavior = .scrollableAxes
```

**Critical:** Using `.scrollableAxes` (not `.never` or `.automatic`) exposes the `env(safe-area-inset-*)` CSS variables to the web content while preventing unwanted automatic content insets. This is required for the CSS layer to work.

### CSS Layer (`markdown-viewer/styles.css`)
```css
.ios-native .app-header {
    padding: calc(0.75rem + env(safe-area-inset-top, 0px))
             calc(1rem + env(safe-area-inset-right, 0px))
             0.75rem
             calc(1rem + env(safe-area-inset-left, 0px));
}

.ios-action-bar {
    padding: 0.75rem
             calc(0.9rem + env(safe-area-inset-right, 0px))
             calc(0.75rem + env(safe-area-inset-bottom, 0px))
             calc(0.9rem + env(safe-area-inset-left, 0px));
}
```

The CSS adds safe area insets to padding on **all four edges**. This ensures:
- Header content doesn't overlap with Dynamic Island or notch (top)
- Controls remain accessible in landscape with notch (left/right)
- Bottom action bar sits above the home indicator (bottom)

### HTML Layer (`markdown-viewer/index.html`)
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
```

The `viewport-fit=cover` meta tag is required to enable the CSS `env(safe-area-inset-*)` variables.

### Testing Safe Area Behavior

Run the test suite to verify safe area CSS is present:
```bash
npm test -- tests/unit/iosRenderer.test.js
```

The test verifies:
1. `.ios-native` class is applied to `<body>` and `<html>`
2. Header CSS includes all four safe area insets
3. Action bar CSS includes all four safe area insets

**To prevent regression:** Do not change `contentInsetAdjustmentBehavior` to `.never` or `.automatic`, and always include all four safe area insets in the CSS for iOS-specific elements that extend to screen edges.

## Why XcodeGen?

The `.xcodeproj` is generated from `project.yml` and is **not committed to git**.
This avoids `.pbxproj` merge conflicts. After project configuration changes,
preserve local owner-managed settings, regenerate in a reviewable location, and
verify the selected scheme and resolved identity before replacing the working
project. Do not overwrite local signing settings as an incidental source update.

## Recent documents

Recent Files is available from the native sidebar and the viewer menu on iPhone
and iPad. Only successfully accepted Files documents are recorded. Each record
retains its provider bookmark and location hint; matching filenames stay separate.
The previous filename-only list is retained but does not grant access. An
unavailable recent offers Retry or Locate without replacing the current document.
For an offline provider, download the file in Files before retrying. Provider move,
revocation and offline behavior still need acceptance on physical devices.

## Relative images

For a Files document, choose **Allow Local Images…** from the viewer menu and
select the folder containing that document. This explicitly grants that view
folder access; reopening or changing views requires selecting it again. Images
use a separate scheme from application assets. Only single-frame PNG, JPEG,
GIF and WebP images are allowed, with a maximum of 8 MiB / 16 million pixels per
image, 8192 pixels per edge, and 64 reads / 32 MiB / 32 million pixels per view.
Paths with traversal, encoded escapes or symlinks are refused. SVG image files
and animated images are intentionally excluded. Offline files must be downloaded
in Files first; folder-provider behavior needs physical-device acceptance.

## Diagram files

Open a diagram fullscreen, then tap **SVG** or **PNG**. iPhone and iPad show a
native Export Diagram sheet with **Save to Files…** and **Share…**. These send
actual files; they do not create hosted links. PNG export is limited to 8 MiB,
8192 pixels per edge and 16 million pixels; SVG is limited to 2 MiB and excludes
active/external content. Finish or cancel one export before starting another.
Changing documents invalidates a pending export. Temporary files are removed on
completion, cancellation, invalidation, and on the next launch after a crash.

Provider reads run off the UI thread with four outstanding operations maximum,
two queued renderer deliveries and a 15-second result deadline. A provider can
continue its system operation after that deadline; late results cannot replace
the document. Download offline files in Files before retrying.

Synthetic hosted WKWebView tests can be run without signing:

```sh
xcodegen generate --spec ios/project.yml --project ios
xcodebuild -project ios/SpecDown.xcodeproj -scheme 'SpecDown Synthetic Tests' \
  -destination 'platform=iOS Simulator,id=YOUR_DISPOSABLE_SIMULATOR_UUID' \
  -derivedDataPath /tmp/specdown-synthetic-tests \
  MARKETING_VERSION=1.0.2 CODE_SIGNING_ALLOWED=NO test
```

Use a newly created disposable simulator only. The tests use synthetic defaults,
files and images, and do not inspect or migrate existing notes. This is unsigned
simulator evidence; third-party providers, physical devices and signed builds
remain separate acceptance surfaces.
