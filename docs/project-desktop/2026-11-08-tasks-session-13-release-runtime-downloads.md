## Observed failure

Release run 42578396842 passed provenance and source checks. Linux packaged
successfully, but Mac and Windows failed during Electron archive downloads with
HTTP 504. One failed-job retry, after fresh human environment approval, repeated
the failure. Publication was skipped in both attempts.

A local probe reproduced HTTP 504 at the official Electron Windows x64 archive
endpoint. The tag contains all eight vendor checksum pins. The earlier
checksum-list dependency does not explain this archive-endpoint failure.
Downloading that same asset through GitHub's official release-asset API
succeeded and matched the vendor SHA-256 pin.

## Workflow correction

Download Electron archives through the official release-asset API before
packaging. Require an exact version, a reviewed pin, matching vendor metadata,
matching byte count and matching SHA-256 before exposing the runtime directory
to electron-builder. Prepare both Intel and ARM archives for universal Mac
builds. Reject missing pins, corrupt bytes and failed transport.

This changes the workflow selected from main. Build jobs still check out the
immutable application tag. Application code, dependencies, version/tag,
signing/notarization checks, human environment approval and publication gates
are unchanged. The workflow's own read-only GitHub token retrieves public
vendor assets; no new secret or repository permission is introduced.
