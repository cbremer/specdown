# Spec: Sharing playbook

**Date:** 2026-08-20

Practical ways to share SpecDown once the web empty state looks like a product.

---

## Demo, not essay

Record a 20–40s mute GIF or native LinkedIn video: drop `diagram-showcase.md` →
Present → pan one diagram → export PNG. Upload the file; don’t _only_ link out.
LinkedIn’s feed favors native video.

First comment on your own post: desktop download links + “try the showcase in
the browser, no install.”

---

## Where to point people

- **Web (the share URL):** https://cbremer.github.io/specdown
- **Source:** https://github.com/cbremer/specdown
- **Desktop:** the latest GitHub Release (macOS universal DMG, Windows NSIS,
  Linux AppImage)
- **Pin** the web URL on the GitHub repo About blurb and on LinkedIn Featured

The web app is still the viewer. The showcase is only the empty state. Drop,
browse, paste a URL, or restore the last session and you are in the document.

---

## Channels

- **LinkedIn** — flagship article + carousel from the hero feature set (last
  card = URL + DMG). Native video or GIF in the post body.
- **Show HN / r/programming / r/markdown** — wait until the showcase URL looks
  like a product, not a drop-zone. Lead with the GIF.
- **Mermaid community** (Discord / discussions) — you make their diagrams
  usable in meetings.
- **Dev.to / Hashnode** — cross-post the flagship for SEO; keep LinkedIn as the
  canonical reach post.
- **Internal/social proof** — if you use it at work, “how my team reviews ADRs”
  outperforms a feature dump.

---

## What not to oversell

- **Don’t** spray iOS until TestFlight. **Do** say “same UI on iPad when you’re
  ready to sideload.”
- **Don’t** fake user counts. Stars and Releases only.
- **Don’t** call it an editor or imply App Store availability.
